## 公开端复用与重构

直接复用的视觉基础包含 `packages/ui/src/tokens.css`、EventBanner、EventNavigation、InfoCard、ContentSection 及原 `apps/web/src/styles/public.css`。导航 aria 标签泛化，活动文本与路由从唯一配置派生。白色粘性导航、蓝绿强调色、字体栈、正文/侧栏骨架保持原基础。

认证复用 AuthForm 和 AccountAccessPanel 的注册、登录、密码校验与重置交互，适配新 API 并显式标记模拟短信。移动端复用原 MobileServiceDock、MobileLiquidGlassBar 及拖拽运动模块，并仅泛化文本/入口；保留原 62px 圆角悬浮玻璃服务栏、抽屉、关闭遮罩、路由变化关闭及拖拽逻辑，没有换成贴边矩形操作条。

PublicShell、首页、交通住宿、联系、资料、FAQ 和个人中心按新配置重构。日程使用逐日四列“时间、题目、主讲人、主持人”，地点为跨列行；可选分组元数据保留原表相邻共享时间、题目、主讲人、主持人和地点，不将主持人拼入讲者栏。原完整 stylesheet 中仍可能有未启用的旧业务选择器；这不表示旧业务组件或路由被接入。

六页导航是用户指定的业务收缩。旧课程助手、晚间活动、签到、支付/发票、旧项目申请、撤稿和共享账号平台均不接入。原人物照片、旧账号/录取记录、数据库迁移和服务器秘密不进入交付。

## 两种横幅来源

1. 实际手册实例：使用获用户授权的同活动原横幅 由branding.heroImage引用的经授权原素材。原站真实浏览器核实的获取链接为 https://panshi-ai4s.tashan.chat/images/panshi-ai4s-camp-banner-20260825.png ，自然尺寸 2048×512；本包没有预填实例素材。实际核对后通过 bind_hero.py 记录相邻派生哈希绑定；生成时保留所选输入图片字节，原日期、场地与该手册属于同一活动。它不是模板重新绘制的图片，也不证明整站已通过浏览器像素验收。
2. 新活动默认框架：`scripts/hero.py` 生成可编辑 SVG，左上最多五个来自新 XLSX 的品牌标识，右上系列活动文字，短展示标题与分开的日期/场地。未提供 brandmarks 时支持 `branding.logo` 回退；未提供标识和系列文本时不编造品牌名。提供现成 heroImage 且派生绑定匹配时复用，不另外叠加品牌图片；缺少/失配绑定则自动使用当前信息的可编辑框架并提示。

默认框架的背景为 `template/frontend/public/brand/banner-background.png`。它通过 imagegen 对原横幅去除旧文字和标识、保留科技图案后生成，是新的清理后图片，与原横幅并非像素一致。独立品牌、文字和日期可编辑，不宣称是适合所有新品牌的通用设计系统或原图无损重建。新活动不得沿用原活动日期、标识和标题来追求视觉相似。

海报引用实际选用的横幅，并从同一配置派生公开事实。现成原图的文字不可编辑；可编辑新框架与原图复用应分别说明。


## 原资料使用

本包不带手册预填答案。只根据新提供的原始文档逐页录入；现成图片须人工核对与规范事实一致，再用显式bind命令记录哈希。原图片不随文本引用自动改图；缺失或失配自动切换可编辑框架并警告。


## 唯一事实源的更新机制

v2 增加小范围、固定字面内容引用：event.title、event.shortTitle、event.dateRange、event.location、travel.address，以及 organizers 的主办单位/协办单位/支持单位三类，用双大括号书写。正文从规范字段展开，不保存另一套名称/日期/机构副本；展开只进行一次，再进入既有输出转义，不是表达式或通用模板引擎。

实际手册 intro 改为这些引用，当前显示文字保持一致。travel.address 只保存完整街道地址，event.location 另存场馆名；文案分别引用，不重复地点。未知容量、窗口和资格仍保持未知。

静态横幅无法随字段改写，因此 `.venv/bin/python scripts/bind_hero.py event.xlsx --confirm-current-facts` 在实际查看图中名称/日期/场地/品牌一致后生成图片旁 `.facts.json`。该文件仅含图片与规范事实 SHA-256，不含第二份可编辑事实。图片或规范事实更新导致绑定不匹配时，自动回退当前信息的可编辑横幅并在 config/manifest/console/UI 提示，不影响无关生成或业务；实际确认同图仍准确后可重新绑定。原图从不被编辑，相邻 metadata 随规范素材与实例追溯快照交付。

## 后端边界

保留原身份、本人数据、私有文件与状态正确性原则，重构为最小固定报名/投稿模型。不保证与旧 API 逐项兼容。readiness 在实际后端边界重新计算；事实未齐仍可准备账号、资料、私有文件及草稿，但不允许相应最终报名、投稿与补料。已有审核记录和资格不随再生成删除。

阿里云短信保留原供应商模板语义，签名与传输改为原生 Node；飞书适配固定两类审核表。官方签名向量和模拟传输通过不表示真实服务已接通，真实服务仍需运营方授权与预发布验收。

## 浏览器与材料证据的范围

本轮云浏览器实际只读观察过原公开站 https://panshi-ai4s.tashan.chat/ ，用于确认原桌面骨架和窄屏服务栏。生成实例的 localhost/file 访问被拒绝，执行环境 Chromium 也不能完成获准的实际浏览器验收；没有绕过访问限制或为验收而外部发布。

v2 可生成同 React 组件的六页 SSR HTML，并能构建、API 测试及渲染 Word/横幅/海报。这些证据分别证明相应阶段，不替代生成网站的真实桌面/手机截图、拖拽、表单或状态刷新验收。具体快照与未验项目见 [VALIDATION.md](VALIDATION.md)。
