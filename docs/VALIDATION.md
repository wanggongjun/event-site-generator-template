## 消费者试用中发现并修正

1. 系统/用户目录pip安装在受限环境失败：改为项目venv和本地缓存，给Linux/macOS与Windows命令。
2. 不同进程隔离会话同时启动同一个共享PG目录，导致测试目录损坏：新增最小postmaster.pid所有者检查、明确一目录一所有者与完整停机规则，启动错误改为可读说明。不自动删PID、重建或恢复数据库。单所有者正常生命周期未重现损坏。
3. 可选仓库生命周期命令依赖未安装模板目录和系统Python：改为指定已安装生成实例和项目venv，实际复跑通过。
4. 明确源码模板打包与生成实例打包区别；实例包含独立RUN.md，日志打印实际PG_DATA_DIR。

原异常测试目录保留，未进行修复或数据删除；交付包不含该目录。

## 复跑入口

按README在模板包目录建立项目venv，然后：

```sh
.venv/bin/python -m unittest discover -s tests -p test_generator.py
```

进入已生成且正常npm install的实例：

```sh
npm run build
npm test
npm run preview:offline
```

可选完整停机回归在模板包根目录执行，必须使用新fixture目录，复用已有生成实例依赖：

```sh
node template/backend/test/shutdown-lifecycle.mjs /absolute/path/to/new-fixture generated/<event.slug> .venv/bin/python
```

Windows最后一个路径使用`.\.venv\Scripts\python.exe`。其自身日志和result.json记录操作结果，不包含真实服务凭据。测试账号与附件是虚构夹具，不能放进生产数据或交付的数据库。
